SAI exposes its functionality through a set of API modules, each represented by a C method table retrieved at runtime. Before using any module, you must initialize the adapter with `sai_api_initialize()` and retrieve the desired method table with `sai_api_query()`.

## Global functions

### `sai_api_initialize()`

Initializes the SAI adapter module. This must be called before any other SAI function. It is **not** an SDK initialization call—it loads the adapter library and supplies the service method table.

```c
sai_status_t sai_api_initialize(
        _In_ uint64_t flags,
        _In_ const sai_service_method_table_t *services);
```

<ParamField path="flags" type="uint64_t">
  Reserved for future use. Must be zero.
</ParamField>

<ParamField path="services" type="const sai_service_method_table_t *">
  Pointer to a caller-provided method table that exposes profile key-value services to the adapter. The table contains two function pointers: `profile_get_value` and `profile_get_next_value`.
</ParamField>

**Returns:** `SAI_STATUS_SUCCESS` on success, otherwise a failure status code.

---

### `sai_api_query()`

Retrieves a pointer to the C-style method table for a specific SAI API module. The returned pointer remains valid until `sai_api_uninitialize()` is called.

```c
sai_status_t sai_api_query(
        _In_ sai_api_t api,
        _Out_ void **api_method_table);
```

<ParamField path="api" type="sai_api_t">
  The SAI API module identifier (e.g., `SAI_API_SWITCH`, `SAI_API_PORT`).
</ParamField>

<ParamField path="api_method_table" type="void **">
  Caller-allocated output pointer that receives the address of the method table. The caller must cast it to the appropriate typed pointer (e.g., `sai_switch_api_t *`).
</ParamField>

**Returns:** `SAI_STATUS_SUCCESS` on success, otherwise a failure status code.

```c
sai_switch_api_t *switch_api = NULL;
sai_status_t status = sai_api_query(SAI_API_SWITCH, (void **)&switch_api);
```

---

### `sai_api_uninitialize()`

Uninitializes the adapter module. Any method tables retrieved via `sai_api_query()` must not be used after this call.

```c
sai_status_t sai_api_uninitialize(void);
```

**Returns:** `SAI_STATUS_SUCCESS` on success, otherwise a failure status code.

---

### `sai_log_set()`

Sets the logging level for a specific SAI API module. The default log level is `SAI_LOG_LEVEL_WARN`.

```c
sai_status_t sai_log_set(
        _In_ sai_api_t api,
        _In_ sai_log_level_t log_level);
```

<ParamField path="api" type="sai_api_t">
  The SAI API module identifier whose log level to configure.
</ParamField>

<ParamField path="log_level" type="sai_log_level_t">
  The desired log verbosity. Valid values: `SAI_LOG_LEVEL_DEBUG` (0), `SAI_LOG_LEVEL_INFO` (1), `SAI_LOG_LEVEL_NOTICE` (2), `SAI_LOG_LEVEL_WARN` (3), `SAI_LOG_LEVEL_ERROR` (4), `SAI_LOG_LEVEL_CRITICAL` (5).
</ParamField>

**Returns:** `SAI_STATUS_SUCCESS` on success, otherwise a failure status code.

---

### `sai_object_type_query()`

Returns the SAI object type of a given object ID.

```c
sai_object_type_t sai_object_type_query(
        _In_ sai_object_id_t object_id);
```

<ParamField path="object_id" type="sai_object_id_t">
  The 64-bit object identifier to query.
</ParamField>

**Returns:** `SAI_OBJECT_TYPE_NULL` when the object ID is invalid; otherwise a valid `SAI_OBJECT_TYPE_XXX` value.

---

### `sai_switch_id_query()`

Returns the switch object ID that owns a given object.

```c
sai_object_id_t sai_switch_id_query(
        _In_ sai_object_id_t object_id);
```

<ParamField path="object_id" type="sai_object_id_t">
  Any SAI object ID. If a switch object ID is passed, it is returned as-is.
</ParamField>

**Returns:** `SAI_NULL_OBJECT_ID` when the object ID is invalid; otherwise the `SAI_OBJECT_TYPE_SWITCH` object ID that owns the given object.

---

### `sai_dbg_generate_dump()`

Generates a diagnostic dump file that may include SAI state information and vendor SDK internals.

```c
sai_status_t sai_dbg_generate_dump(
        _In_ const char *dump_file_name);
```

<ParamField path="dump_file_name" type="const char *">
  Full filesystem path for the output dump file.
</ParamField>

**Returns:** `SAI_STATUS_SUCCESS` on success, otherwise a failure status code.

---

### `sai_object_type_get_availability()`

Queries the remaining hardware resource capacity for a given SAI object type.

```c
sai_status_t sai_object_type_get_availability(
        _In_ sai_object_id_t switch_id,
        _In_ sai_object_type_t object_type,
        _In_ uint32_t attr_count,
        _In_ const sai_attribute_t *attr_list,
        _Out_ uint64_t *count);
```

<ParamField path="switch_id" type="sai_object_id_t">
  The switch object ID to query against.
</ParamField>

<ParamField path="object_type" type="sai_object_type_t">
  The SAI object type for which to check resource availability.
</ParamField>

<ParamField path="attr_count" type="uint32_t">
  Number of attributes in `attr_list`.
</ParamField>

<ParamField path="attr_list" type="const sai_attribute_t *">
  Optional attribute list to distinguish resource sub-types (e.g., ACL table stage).
</ParamField>

<ParamField path="count" type="uint64_t *">
  Output: number of objects of the given type that can still be created.
</ParamField>

**Returns:** `SAI_STATUS_NOT_SUPPORTED` if the object type does not support resource accounting; otherwise `SAI_STATUS_SUCCESS`.

## Status codes (`sai_status_t`)

All SAI functions that return `sai_status_t` use the following codes. On POSIX systems the values are negative integers; on Windows they map to positive codes.

| Constant | Description |
|----------|-------------|
| `SAI_STATUS_SUCCESS` | Operation completed successfully. |
| `SAI_STATUS_FAILURE` | General failure. |
| `SAI_STATUS_NOT_SUPPORTED` | The request is not supported by this implementation. |
| `SAI_STATUS_NO_MEMORY` | Insufficient memory to complete the operation. |
| `SAI_STATUS_INSUFFICIENT_RESOURCES` | Insufficient system resources. |
| `SAI_STATUS_INVALID_PARAMETER` | An invalid parameter was passed. |
| `SAI_STATUS_ITEM_ALREADY_EXISTS` | An item already exists (e.g., duplicate route). |
| `SAI_STATUS_ITEM_NOT_FOUND` | The requested item does not exist. |
| `SAI_STATUS_BUFFER_OVERFLOW` | The data was too large for the provided buffer. Retry with the count returned by the callee. |
| `SAI_STATUS_INVALID_PORT_NUMBER` | Invalid port number. |
| `SAI_STATUS_INVALID_PORT_MEMBER` | Invalid port member. |
| `SAI_STATUS_INVALID_VLAN_ID` | Invalid VLAN ID. |
| `SAI_STATUS_UNINITIALIZED` | Object is uninitialized. |
| `SAI_STATUS_TABLE_FULL` | Hardware table is full. |
| `SAI_STATUS_MANDATORY_ATTRIBUTE_MISSING` | A mandatory attribute was not provided. |
| `SAI_STATUS_NOT_IMPLEMENTED` | The function is not implemented. |
| `SAI_STATUS_ADDR_NOT_FOUND` | Address not found. |
| `SAI_STATUS_OBJECT_IN_USE` | The SAI object is still in use and cannot be removed. |
| `SAI_STATUS_INVALID_OBJECT_TYPE` | Invalid SAI object type was passed. |
| `SAI_STATUS_INVALID_OBJECT_ID` | Invalid SAI object ID (e.g., already deleted). |
| `SAI_STATUS_INVALID_NV_STORAGE` | NV storage is invalid or corrupt. |
| `SAI_STATUS_NV_STORAGE_FULL` | NV storage is full. |
| `SAI_STATUS_SW_UPGRADE_VERSION_MISMATCH` | Version mismatch during in-service upgrade. |
| `SAI_STATUS_NOT_EXECUTED` | Operation was not executed. |
| `SAI_STATUS_STAGE_MISMATCH` | Object pipeline stage mismatch. |
| `SAI_STATUS_INVALID_ATTRIBUTE_0` | Attribute at index N is invalid (range 0x00010000–0x0001FFFF). |
| `SAI_STATUS_INVALID_ATTR_VALUE_0` | Attribute value at index N is invalid (range 0x00020000–0x0002FFFF). |
| `SAI_STATUS_ATTR_NOT_IMPLEMENTED_0` | Attribute at index N is supported but not implemented (range 0x00030000–0x0003FFFF). |
| `SAI_STATUS_UNKNOWN_ATTRIBUTE_0` | Attribute at index N is unknown/out of range (range 0x00040000–0x0004FFFF). |
| `SAI_STATUS_ATTR_NOT_SUPPORTED_0` | Attribute at index N is not supported on this platform (range 0x00050000–0x0005FFFF). |

<Tip>
For attribute-related errors, the offset from the base constant is the array index of the offending attribute in the list passed to the SAI API call. Use the helper macros `SAI_STATUS_IS_INVALID_ATTRIBUTE(x)`, `SAI_STATUS_IS_INVALID_ATTR_VALUE(x)`, etc., to test the error category.
</Tip>

## Initialization sequence

The typical lifecycle for a SAI consumer:

```c
#include <sai.h>

/* Service callbacks provided to the adapter */
static const char *profile_get_value(sai_switch_profile_id_t profile_id,
                                     const char *variable) {
    (void)profile_id;
    if (strcmp(variable, "some_key") == 0) return "some_value";
    return NULL;
}

static int profile_get_next_value(sai_switch_profile_id_t profile_id,
                                  const char **variable,
                                  const char **value) {
    (void)profile_id; (void)variable; (void)value;
    return -1; /* no more entries */
}

int main(void) {
    sai_service_method_table_t services = {
        .profile_get_value      = profile_get_value,
        .profile_get_next_value = profile_get_next_value,
    };

    /* 1. Initialize the adapter */
    sai_status_t status = sai_api_initialize(0, &services);
    if (status != SAI_STATUS_SUCCESS) return 1;

    /* 2. Set desired log level */
    sai_log_set(SAI_API_SWITCH, SAI_LOG_LEVEL_INFO);

    /* 3. Retrieve a method table */
    sai_switch_api_t *switch_api = NULL;
    status = sai_api_query(SAI_API_SWITCH, (void **)&switch_api);
    if (status != SAI_STATUS_SUCCESS) return 1;

    /* ... use switch_api->create_switch(), etc. ... */

    /* 4. Uninitialize when done */
    sai_api_uninitialize();
    return 0;
}
```
